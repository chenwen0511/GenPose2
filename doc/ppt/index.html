07 / 28
实例级 6D + 尺寸

它做什么

GenPose2（论文 GenPose++）做实例级 6D 位姿 + 包围盒尺寸。不负责分割——输入已含实例 mask。

一帧输入
  • RGB · color.png
  • 深度 · depth.exr（米）
  • 实例 mask · mask.exr
  • 相机内参 · meta.json
最终输出
  • pose：[N, 4, 4] 刚体变换
  • length：[N, 3] → size_3d
  • 多实例一次 batch 前向
  • 可选 tracking 用上一帧初值
关键直觉：位姿不是「算一个数」，而是从「在当前点云下，哪些姿态更像真的」这一概率分布里采样出来的。

为何不回归

  • 学「往哪走上山」（坡度场）
  • 从雾里顺着坡走回峰顶
  • 多走几次 → 两座山都可能到
  • 再交给 Energy 挑更可信的峰

三个词 · 先记分布

什么是分布

把所有可能的 6D 位姿想成一张地形图：山越高 = 在这份点云下越像真姿态。这张图就叫条件分布 p(位姿 | 观测)。

Peak · 峰
高山
更可能正确的姿态簇
Valley · 谷
山谷
折中均值常掉在这里
Multi-modal
多峰
对称圆盘常见两座山
料盘只见前半盘面时：平移 / 倾角往往一座山；绕法向自转则是一整圈「等高」——分布在那个方向上是平的。

10 / 28
扩散 · 加雾与除雾

扩散与采样

训练 · 正向扩散
  • 真姿态 = 清晰照片
  • 一步步加噪 = 往照片上喷雾
  • 喷得越狠（t 越大）越糊
  • 网络学：在这团雾里，往哪走更像原图
推理 · 反向采样
  • 从纯噪声出发（整屏雾）
  • 跟着 score 坡度一步步除雾
  • ODE 积分 = 顺着风向下山/上山
  • 多采几次 = 多条登山路径 → K 个候选
一句话：扩散是训练时把答案搅糊；采样是推理时从糊里走回清晰姿态。Score 就是「每一步该往哪挪」。

Structure · ScoreNet
12 / 28
结构 = 坡度仪 + 登山向导

Score 结构

骨干 · 看地形
  • ROI RGB → DINOv2（外观）
  • 点云 → PointNet++（几何）
  • 融成 pts_feat：这片「山」的条件
  • 位姿 9 维 = 地图上的坐标
头 + 采样 · 走路
  • 输入：当前糊位姿 + 噪声级别 t
  • 输出：score = 下一步该往哪挪
  • ODE 反复调用 = 一步步除雾
  • 重复 K=50 次 = 50 条登山路径
采样时间线：t 大（整屏雾 / 纯噪声）→ t 中（依稀靠近物体）→ t→0（贴合点云的清晰 6D）。换随机种子 = 换一条路，可能爬上另一座峰。

Structure · Energy & Scale
13 / 28
筛选 + 尺寸

Energy / Scale

EnergyNet · 同构异训
  • 结构几乎同 ScoreNet
  • 给每个候选打 rot / trans 能量分
  • 本仓库：能量越高越优先
  • retain_ratio=0.4 裁掉后 60%
  • 四元数平均；可选 DBSCAN
ScaleNet · 小回归头
  • 输入：pts_feat + 已定 axes
  • 输出：[l,w,h]，不参与扩散
  • ~5 MB，远小于 Score/Energy
  • 轴向错了尺寸会对错轴
  • 料盘型号固定 → 可写死跳过

汇流前先对齐

标签约定

风险
  • 坐标系 / 单位不一致（m vs mm）
  • 抓取点与物体中心混用
  • 教师误差被当成真值放大
  • 三路自转定义互相冲突
规则
  • 统一相机系 + 米制写 meta
  • 明确标签语义：盘心 or 抓取点
  • 置信度 / 可视化质检后再入库
  • 自转统一固定，只留 xyz + 法向

# GenPose2 数据合成说明（`data_factory/`）

本文说明仓库内 `data_factory/` 如何从电子料盘 CAD 生成 GenPose2 可用数据。产出格式与 [`数据集格式.md`](./数据集格式.md) 中的 SOPE 约定一致；料盘边缘场景的训练策略见 [`料盘边缘场景训练.md`](./料盘边缘场景训练.md)。

---

## 1. 目录里有什么

| 文件 | 作用 |
|------|------|
| `generate_sope_dataset.py` | **主流程（单物体）**：CAD → SOPE 训练集/测试集（RGB + depth + mask + meta）+ `obj_meta.json` |
| `generate_sope_multitray.py` | **主流程（密排遮挡）**：1–10 片 × 间距 6/26/46mm × 每组合 50 帧；边缘视角 + 挡板裁切 |
| `process_cad.py` | **辅助**：CAD → 中心化 1024 点 PLY（模拟 GenPose 输入点云，含侧面白色塑料噪点） |
| `smt_tray_01.STEP` 等 CAD | 料盘三维模型；脚本会按候选文件名自动查找 |
| `datasets/build_real_eval_from_sam3.py` | **真实数据**：无标签 RGB-D → 调 SAM3 TensorRT `/infer` → 按实例切成 SOPE `test` 集 |
| `datasets/ui_display/app.py` | Gradio 样本浏览器（RGB / Depth / Mask / meta + **3D GLB**，←→ 翻页） |
| `datasets/ui_display/scene_glb.py` | 预览用：深度点云 + 相机视锥 + 各料盘姿态轴/bbox → GLB（写 `_glb_cache/`，不改训练数据） |

当前脚本默认按顺序查找 CAD：

1. `data_factory/smt_tray_01.STEP`
2. `data_factory/smt_tray.PLY`
3. `data_factory/零件1.STEP`

依赖：`trimesh`（STEP 需 `cascadio`）、`numpy`、`pillow`；保存 EXR 需 OpenCV 且 `OPENCV_IO_ENABLE_OPENEXR=1`（脚本已自动设置，也可回退 `OpenEXR`）。

## 2. 两条生产线分别做什么

```
                    ┌─────────────────────────────────────┐
 CAD (PLY/STEP) ───►│ process_cad.py                      │
                    │ 表面采样 → 主体/侧面分类 → FPS→1024 │
                    │ → 中心化 → *_genpose.ply            │
                    └─────────────────────────────────────┘
                                      （点云可视化 / 调试输入形态）

                    ┌─────────────────────────────────────┐
 CAD (PLY/STEP) ───►│ generate_sope_dataset.py             │
                    │ 中心化 mesh → 随机姿态              │
                    │ → 点采样 z-buffer 渲染              │
                    │ → color/depth/mask/meta             │
                    │ → Meta/obj_meta.json                │
                    └─────────────────────────────────────┘
                                      （真正给训练用的 SOPE 数据）
```

- **训练请走合成脚本**：单物体用 `generate_sope_dataset.py`；**料架密排/上沿遮挡**用 `generate_sope_multitray.py`（推荐作为 `train_set_1st_0810` 主数据）。
- **`process_cad.py` 不生成训练帧**：它模拟「网络看到的 1024 点云长什么样」（主体顶面 + 稀疏侧面噪点），便于检查 CAD 朝向、尺度、噪点策略。

## 2.1 多料盘密排合成（`generate_sope_multitray.py`）

对齐 [`料盘边缘场景训练.md`](./料盘边缘场景训练.md) 的数据需求：

| 因子 | 取值 |
|------|------|
| 料盘数量 | 1 … 10 |
| 面间距 | 6 / 26 / 46 mm（中心距 = 厚度 + 间距） |
| 每组合帧数 | 50（默认 40 train + 10 test） |
| 合计 | **1500** 帧 |

几何与渲染：

1. CAD 中心化后薄轴为局部 Z；先直立（薄轴→排列方向 Y），再整体放到相机前；
2. 多实例共用表面采样，**z-buffer 互遮挡**，`mask_id = 1..n`；
3. ~75% 帧偏边缘俯视；~70% 帧用挡板清空画面下半，模拟「只见上沿」；
4. `meta.json` / `obj_meta.json` 直接写 **cutoop** 可读格式。

```bash
conda activate genpose2
python data_factory/generate_sope_multitray.py \
  --training_dir datasets/train_set_1st_0810 \
  --cad_dir data_factory \
  --n_samples_per_tray 40000 \
  --seed 42

# 同步配置后训练
# configs/obj_meta.json 会由脚本自动写入
bash scripts/train_score_tray_0810.sh
```

## 3. `generate_sope_dataset.py`：SOPE 数据生成（详解）

### 3.1 做什么

从料盘 CAD 批量合成 GenPose2 / Omni6DPose **SOPE 风格**数据：

- 每帧：`{id}_color.png`、`{id}_depth.exr`、`{id}_mask.exr`、`{id}_meta.json`
- 全局：`Meta/obj_meta.json`（含 `oid`、尺寸、对称性）

默认：**600 帧 train + 200 帧 test**，单实例（mask id = 1）。

### 3.2 为什么这样设计

| 设计点 | 原因 |
|--------|------|
| 无 OpenGL / 纯点采样 z-buffer | 不依赖显卡渲染器，环境简单，在服务器上可复现 |
| mesh 先中心化 | 姿态以几何中心为原点，与 GenPose 点云去中心习惯一致 |
| 随机 SO(3) 四元数 + 前方工作区平移 | 覆盖多视角；物体始终在相机前方可投影区域 |
| 深度单位米、EXR 浮点 | 与官方 SOPE / cutoop 加载约定一致 |
| 同步写 `obj_meta.json` | 每帧 `oid` 必须能在全局元数据里找到，否则加载器跳过样本 |
| 圆柱对称标成 `x/y: any` | 料盘近似圆柱，训练时对称损失/评估需要正确对称标签 |

### 3.3 流水线逐步说明

#### Step A：加载 CAD

`load_mesh(cad_dir)`：

1. 在候选路径中找第一个存在的文件；
2. `trimesh.load(..., force='mesh')`；
3. 若得到 `Scene`（常见于 STEP），合并全部子 `Trimesh`。

#### Step B：中心化

`center_mesh`：顶点减去顶点均值，使几何中心到原点。随后：

$$
\mathrm{bbox\_side\_len} = \mathrm{bounds}_{max} - \mathrm{bounds}_{min}
$$

该三维边长写入每帧 `meta.json` 与全局 `obj_meta.json`。

#### Step C：随机位姿

- **旋转**：`random_quaternion_wxyz()`，在 SO(3) 上均匀采样，顺序固定 `[w,x,y,z]`。
- **平移**：`random_translation()`，单位米：

| 轴 | 默认范围 |
|----|----------|
| X / Y | `[-0.08, 0.08]` |
| Z | `[0.55, 0.95]`（相机前方） |

相机固定在原点、看向 +Z（针孔模型）；物体位姿直接写在相机坐标系。

#### Step D：渲染一帧 `render_frame`

不走光栅化管线，而是：

1. 在 mesh 表面均匀采样 `N_SURFACE_SAMPLES`（默认 **80000**）个点；
2. 变换到相机系：`P_cam = P_obj @ R.T + t`；
3. 针孔投影：

$$
u = f_x \frac{X}{Z} + c_x,\quad
v = f_y \frac{Y}{Z} + c_y
$$

4. 过滤：`Z>0` 且像素落在 `640×480` 内；
5. **Z-buffer**：深度缓冲初始化为 `+inf`，同像素保留最小深度（`np.minimum.at`）；未命中像素再置 `0`。**不可**初始化为 `0`，否则 `min(0, z)` 会得到全零深度；
6. **Mask**：有投影的像素写实例 ID `1`；
7. **RGB**：仅对最前表面着色（法线 Lambertian，白塑料 `RGB≈225`，环境光 0.35 + 漫反射 0.65），背景深灰 `64`。

默认相机内参（与 `meta.json` 一致）：

| 参数 | 值 |
|------|-----|
| 分辨率 | 640 × 480 |
| `fx` / `fy` | 600 |
| `cx` / `cy` | 320 / 240 |

#### Step E：落盘

每个 split 目录：

```
{training_dir}/SOPE/000000/{train|test}/Omni6DPose/000000/
├── 000000_color.png
├── 000000_depth.exr      # float32，米；0=无效
├── 000000_mask.exr       # float32 = instance_id/255（加载时 *255 → uint8）；0 背景 / 1 物体
├── 000000_meta.json
├── 000001_...
└── ...
```

`mask.exr` 按 GenPose2 / cutoop 约定写入：像素值为 `id/255` 的 float32（不是直接存 uint8）。

注意默认输出根目录拼写为 **`./trainging`**（脚本里的原样路径，不是 `training`）。

`meta.json` 关键字段：

- `camera.intrinsics`：上表内参；
- `objects[0].mask_id = 1`；
- `objects[0].meta.oid = "smt_factory-smt_tray-000001"`；
- `quaternion_wxyz` / `translation`：本帧随机姿态；
- `bbox_side_len`：中心化后 mesh 包围盒边长；
- `is_valid = true`。

#### Step F：全局 `obj_meta.json`

写到 `{training_dir}/Meta/obj_meta.json`：

```json
{
  "objects": [
    {
      "oid": "smt_factory-smt_tray-000001",
      "class_name": "smt_tray",
      "class_label": 0,
      "bbox_side_len": [...],
      "symmetry": {
        "any": false,
        "x": "any",
        "y": "any",
        "z": "none"
      }
    }
  ]
}
```

圆柱体：绕盘面内两轴（脚本里标为 x/y）任意旋转对称；若你的 CAD 轴向约定不同，需改对称标签与坐标系定义，否则损失会对「不可辨自由度」乱惩罚。

### 3.4 命令行用法

在仓库根目录：

```bash
# 默认：600 train + 200 test → ./trainging/
python data_factory/generate_sope_dataset.py

# 自定义数量与输出目录（示例：本仓库常用合成集）
python data_factory/generate_sope_dataset.py \
  --training_dir datasets/train_set_1st_0810 \
  --cad_dir data_factory \
  --n_train 600 \
  --n_test 200 \
  --n_samples 80000 \
  --seed 42
```

| 参数 | 默认 | 含义 |
|------|------|------|
| `--training_dir` | `./trainging` | 输出根目录 |
| `--cad_dir` | `data_factory` | CAD 所在目录 |
| `--n_train` | 600 | 训练帧数 |
| `--n_test` | 200 | 测试/验证帧数（代码里 `test/` 兼作 val） |
| `--n_samples` | 80000 | 每帧表面采样点数（越大越密、越慢） |
| `--seed` | 42 | 随机种子 |

### 3.5 生成后接到训练

```bash
# 1) 拷贝全局物体元数据到项目配置
cp ./trainging/Meta/obj_meta.json configs/obj_meta.json

# 2) 训练时 --data_path 指向 SOPE 根（不是 train 子目录）
#    例如 scripts/train_score.sh 里把路径换成：
#    --data_path ./trainging/SOPE
```

加载器会找：

```
SOPE/*/train/...
SOPE/*/test/...
```

与官方 SOPE 布局一致（见 [`数据集格式.md`](./数据集格式.md)）。

### 3.6 能力与局限（合成质量）

**已覆盖：**

- 单物体、随机姿态、标准四件套、对称元数据；
- 无需 GPU 渲染即可批量出数据。

**尚未覆盖 / 需知：**

- **单实例**：当前 mask 只有 id=1，没有密排多盘互遮挡；
- **非物理渲染**：无真实纹理/反光/阴影，RGB 为法线着色；深度是采样点投影，不是完整光栅化，可能有孔洞；
- **无背景杂物**：背景纯色，域间隙相对真实货架/料架较大；
- **轴向假设**：对称标签按「圆柱、某两轴 any」写死，CAD 朝向若不是脚本假设，需先旋转模型或改标签；
- 若要做「料架密排只见上沿」场景，需在此脚本上扩展：多实例摆放、遮挡、相机俯视边缘视角等（本仓库当前脚本未实现）。

## 4. `process_cad.py`：CAD → GenPose 风格 1024 点云（详解）

### 4.1 做什么

把料盘 CAD 变成 **中心化后的 1024 点**（可选存 PLY），专门模拟：

- 正面主要看到的 **158mm 盘体顶面**；
- 圆柱侧面白色塑料造成的 **稀疏反射噪点**（带微小位置抖动）。

用于检查「网络输入点云」形态，**不是** SOPE 训练四件套生成器。

### 4.2 为什么这样设计

真实深度相机打在白色塑料侧壁上，常出现稀疏、抖动的噪点；若点云只采完整 CAD 表面，训练分布会偏「过干净」。脚本把侧面点单独稀疏化并加抖动，主体顶面保留，更接近正面观测。

### 4.3 算法步骤

1. **加载 mesh**（同 SOPE 脚本，支持 Scene 合并）。
2. **表面均匀采样 20000 点**（`trimesh.sample.sample_surface`）。
3. **按几何分类** `_classify_tray_points`（假设 **Z-up，盘面在 XY**）：
   - 径向距离 `< 半径×(1+5%)` 且 `z > z中位数` → **主体顶面**；
   - 径向超出主体且上半部分 → **侧面噪点候选**。
4. **侧面**：按 `side_noise_ratio`（默认 0.18）稀疏抽样，叠加高斯抖动 `side_position_jitter`（默认 0.0008 m）。
5. **合并**主体 + 侧面；不足 1024 则有放回补齐。
6. **FPS（最远点采样）** 精确采到 1024 点，空间分布更均匀。
7. **减质心**中心化；可选导出 `*_genpose.ply`。

默认料盘主体直径：`TRAY_MAIN_DIAMETER_MM = 158.0`。

### 4.4 用法

```bash
# 脚本 __main__ 会处理存在的 smt_tray.PLY / 零件1.STEP
python data_factory/process_cad.py
```

或在代码中调用：

```python
from data_factory.process_cad import process_cad_to_genpose_input

pts, centroid = process_cad_to_genpose_input(
    "data_factory/smt_tray.PLY",
    output_ply="data_factory/smt_tray_genpose.ply",
    num_points=1024,
    main_diameter_mm=158.0,
    side_noise_ratio=0.18,
    side_position_jitter=0.0008,
)
# pts: (1024, 3)，已中心化；centroid 为减去的中心（原坐标系）
```

**重要假设：** CAD 必须先摆成 Z-up（盘面水平）。朝向不对时，主体/侧面分类会错，侧面噪点策略失效。

## 6. 推荐工作流（从 CAD 到开训）

```
1. 准备 CAD
   - 确认单位（脚本按「米」写平移；cascadio 加载 STEP 时常已是米）
   - 旋转到 Z-up（盘面 XY）
   - 放到 data_factory/（优先 `smt_tray_01.STEP`）

2. （可选）检查点云形态
   python data_factory/process_cad.py
   → 用 CloudCompare / MeshLab 看 *_genpose.ply
     是否主体顶面为主、侧面噪点稀疏合理

3. 生成 SOPE
   python data_factory/generate_sope_dataset.py --n_train 600 --n_test 200

4. 挂接训练
   cp ./trainging/Meta/obj_meta.json configs/obj_meta.json
   修改 train_*.sh 的 --data_path 为 ./trainging/SOPE

5. 抽查几帧
   - color / mask 对齐
   - depth 非全 0，mask 内有效深度足够（训练会跳过有效点过少的实例）
   - meta 中 translation 与画面中物体位置大致一致
```

## 7. 真实货架数据 → SOPE 评测集（SAM3）

无 6D 标签的真实 RGB-D（每样本目录含 `rgb.png` / `depth.png` / `camera.json`）可走：

```bash
# 依赖本机 SAM3 TensorRT HTTP（默认 http://127.0.0.1:18003/infer）
python datasets/build_real_eval_from_sam3.py \
  --src_root /data/03-data/pose_training_data \
  --out_root datasets/eval_set_real_data_with_shelf_0810 \
  --api_url http://127.0.0.1:18003/infer \
  --prompt "Plastic Reel Connected With Tape"
```

要点：

- **每个 SAM3 检测实例 → 单独一帧**（`mask_id=1`），落在 `SOPE/.../test/...`
- depth：`depth.png` 毫米 → `depth.exr` 米；内参来自 `camera.json` 的 `cam_K`
- **无真实位姿**：旋转为单位四元数，平移为 mask 内深度质心反投影（`comments` 含 `pseudo_pose`）
- 产物目录默认被 `.gitignore` 忽略；映射关系见输出根下 `manifest.json`

Gradio 浏览（默认根可改）：

```bash
conda activate genpose2
# 合成密排集
python datasets/ui_display/app.py --port 7861 \
  --root datasets/train_set_1st_0810
# 或真实评测集
python datasets/ui_display/app.py --port 7861 \
  --root datasets/eval_set_real_data_with_shelf_0810
```

浏览器打开后选 **train/test**（点扫描；若无 train 会自动切到有数据的 split）。键盘 **← / →** 翻页。

页面除 RGB / Depth / Mask / meta 外，还有 **3D 点云 GLB**（`gr.Model3D`）：

- RGB-D 点云（实例优先着色，背景变暗）
- 相机视锥 + 相机坐标轴（观察视角）
- 每个料盘：姿态轴、原点球、bbox 线框（来自 `meta` 的 quat/t / `bbox_side_len`）

GLB 缓存于 `datasets/ui_display/_glb_cache/`（已 gitignore），**不改动** SOPE 四件套与训练路径。

## 8. 与官方 Omni6DPose SOPE 的关系

| 项目 | 官方 SOPE | 本仓库 `data_factory` |
|------|-----------|------------------------|
| 全称 | Simulated 6D Object Pose Estimation Dataset | 对齐同名目录约定（合成训练子集） |
| 目录层级 | `SOPE/PATCH/train|test/SCENE/...` | 同样结构，固定 `000000/.../Omni6DPose/000000` |
| 每帧四件套 | 有 | 有 |
| 渲染方式 | 仿真引擎（复杂光照/场景） | 点采样 z-buffer + 法线着色 |
| 多物体/场景多样性 | 丰富 | 单物体脚本 + **密排多料盘**（`generate_sope_multitray.py`）；背景仍偏简 |
| `obj_meta` | 多类多实例 | 单类料盘 oid（smt_tray），可多实例同帧 |

因此：本合成数据适合 **料盘专用过拟合/冷启动**；若要泛化到复杂货架，需增强场景多样性或混入真实数据（ROPE）做评估。

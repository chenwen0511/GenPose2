# 料盘边缘场景：GenPose2 重训练指南

本文面向**料架密排料盘**场景：相机几乎只能看到暴露的上沿/侧沿，料盘为**对称圆盘**，遮挡重、点云残缺。目标是指导如何用专用数据**从零训练**（允许过拟合），使模型在可见边缘点云上给出可用姿态。

相关推理说明见 [`推理过程详解.md`](./推理过程详解.md)；三网权重默认路径见 `configs/conf.json` → `genpose2`。

---

## 1. 三网各自做什么

推理流水线（`runners/infer.py` → `GenPose2.inference`）：

```
点云(+RGB 特征)
      │
      ▼
 ScoreNet  ──► 多样候选 6D 位姿（扩散 / ODE 采样）
      │
      ▼
 EnergyNet ──► 给候选打能量分并排序，聚合出最优位姿
      │
      ▼
 ScaleNet  ──► 输出 size_3d [l,w,h]，并可校正轴向
```

| 权重 | 网络类 | 角色 | 约大小 |
|------|--------|------|--------|
| `results/ckpts/ScoreNet/scorenet.pth` | `PoseScoreNet` | 从残缺点云采样候选姿态 | ~114 MB |
| `results/ckpts/EnergyNet/energynet.pth` | `PoseEnergyNet` | 能量排序，挑更可信姿态 | ~114 MB |
| `results/ckpts/ScaleNet/scalenet.pth` | `ScaleNet` | 估计包围盒尺寸 | ~5 MB |

训练入口：

```bash
bash scripts/train_score.sh    # --agent_type score
bash scripts/train_energy.sh   # --agent_type energy
bash scripts/train_scale.sh    # --agent_type scale；依赖已训好的 ScoreNet 特征
```

脚本内把 `--data_path Omni6DPose_SOPE_PATH` 换成你的 SOPE 风格数据集路径。

## 2. 场景难点（为什么通用权重不够）

典型画面：料盘竖插在料架槽内，下半被挡板遮住；密排时多数实例只露出**一条上沿弧线 + 少量盘面**。

| 难点 | 影响 |
|------|------|
| 遮挡极重 | 点云几乎只剩边缘，形状线索少 |
| 密排更密 | 实例 mask 易粘连/漏检；相邻盘串扰 |
| 对称圆盘 | **绕法向自转不可辨**，完整 6D 存在固有多解 |
| 薄盘边缘 | Scale / 厚度方向对噪声敏感 |

结论：Omni6DPose 通用预训练对「货架商品」有帮助，但对「密排圆盘只见上沿」帮助有限。**专用数据 + 从零训（甚至过拟合）是合理路线。**

---

## 3. 先定标签：只监督「可观测」自由度

对称圆盘 + 边缘观测下，不要强行学满完整旋转群。

| 自由度 | 边缘点云能否支撑 | 训练建议 |
|--------|------------------|----------|
| 盘心位置 `xyz` | 可以 | **必须监督**（mm 级验收） |
| 盘面朝向（法向 / 倾角） | 一般可以 | **必须监督**（弧线所在平面） |
| 绕法向自转（盘面内旋转） | **基本不能** | 固定为 0，或从 loss 中剔除 |
| 尺寸 `l,w,h` | 料盘型号固定时已知 | **可写死**，ScaleNet 可弱化/跳过 |

若标签里自转角任意抖动，Score/Energy 的 loss 会对「学不会的量」震荡，表现为训不稳、过不了拟合。

推荐姿态约定（实现时可二选一）：

1. **物理约定**：盘面近似竖直站立；自转角恒 0；监督平移 + 盘面法向（或等价旋转矩阵中可观测部分）。
2. **槽位约定**：以料架槽方向为参考，姿态相对槽位定义，减少绝对旋转歧义。

## 4. 训练策略总览

### 4.1 推荐顺序

```
1) 准备料盘边缘专用 SOPE 数据（见第 5 节）
2) ScoreNet：随机初始化，从零训（主攻「边缘点云 → 姿态分布」）
3) EnergyNet：候选发散或密排多解明显时再训
4) ScaleNet：尺寸固定则跳过，推理写死 size_3d；否则接 ScoreNet 特征再训
```

### 4.2 「权重置零 / 过拟合」怎么理解

- **可以**：不用官方 `scorenet.pth` 等预训练，随机初始化后在专用集上训到过拟合。
- **指的是**：不加载通用权重（默认 `--use_pretrain` 为 False 即可），**不是**把网络参数手工写成全 0 或改坏结构。
- **闭环场景**（固定料盘型号、固定料架、固定相机高度）允许过拟合到该分布。

### 4.3 各网是否必训

| 网络 | 料盘边缘场景 |
|------|----------------|
| ScoreNet | **必训** |
| EnergyNet | 建议训；若单候选已稳可后置 |
| ScaleNet | 尺寸固定 → **可不训**；推理硬编码 `[l,w,h]` |

`train_scale.sh` 需 `--pretrained_score_model_path` 指向**你刚训好的** ScoreNet，而不是官方权重。

## 5. 数据准备（比「数据量大」更重要）

数据需对齐仓库 SOPE / Omni6DPose 训练管线（见 `datasets/datasets_omni6dpose.py`：姿态为四元数 + 平移等字段）。具体落盘格式以 Omni6DPoseAPI / 现有 SOPE 目录为准；以下强调**内容分布**。

### 5.1 必须覆盖的现象

- **只保留上沿 / 侧沿点云**：与线上「只见暴露边缘」一致，不要只训完整盘面。
- **密度梯度**：从当前密度到「更密一档」都要有（线上往往更挤）。
- **遮挡比例**：轻度 / 中度 / 重度；下半遮挡是常态。
- **视角与标定**：与实机相机内参、高度、俯仰一致。
- **脏 mask**：刻意加入漏检、粘连、锯齿，贴近 SAM3/分割实况。

### 5.2 标签质量

- GT 为物体在**相机系**下的完整可观测姿态（按第 3 节约定处理自转）。
- 同一帧多实例：每个料盘独立 instance id，与 mask 一致。
- 深度单位与训练读取约定一致（常见为米；与 `推理过程详解.md` 深度说明对齐）。

### 5.3 分割与姿态的分工

密排场景里往往是：

> **实例分割质量 > 姿态网络能力**

训练姿态网前，先保证线上 mask 策略（SAM3 提示词、阈值、后处理）稳定；否则再好的 ScoreNet 也会被串盘拖垮。

## 6. 具体训练命令

环境：`conda activate genpose2`，在仓库根目录执行。

**推荐（`train_set_1st_0810` 密排合成冷启动）**——已写好路径与 log_dir：

```bash
# 数据合成已迁至 ../data_factory_blender（见 learning/数据合成.md）
# 确认 configs/obj_meta.json 存在后：
bash scripts/train/train_score_tray_0810.sh
bash scripts/train/train_energy_tray_0810.sh
bash scripts/train/train_scale_tray_0810.sh
```

可用环境变量覆盖：`DATA_PATH` / `BATCH_SIZE` / `N_EPOCHS` / `CUDA_VISIBLE_DEVICES`；Scale 脚本还可用 `SCORE_CKPT`。

训练前可用样本浏览器核对点云与姿态标签（含 3D GLB）：

```bash
python datasets/ui_display/app.py --port 7861 --root datasets/train_set_1st_0810
```

### 6.1 ScoreNet（通用入口）

若不用 `*_tray_0810.sh`，可编辑 `scripts/train_score.sh`：

```bash
# 将 Omni6DPose_SOPE_PATH 换成你的数据集根目录
--data_path /path/to/your_tray_SOPE \
--log_dir ScoreNet_tray \
--agent_type score \
--n_epochs 50 \          # 过拟合场景可加长，盯 train loss
--batch_size 128 \       # 按显存下调
--dino pointwise \
--is_train
```

```bash
bash scripts/train_score.sh
```

检查点通常落在 `results/ckpts/<log_dir>/`（以 `runners/trainer.py` / `PoseNet` 实际保存名为准）。训完后用于推理的路径写到 `configs/conf.json`：

```json
"genpose2": {
  "score_ckpt": "results/ckpts/ScoreNet_tray_0810/....pth",
  "energy_ckpt": "...",
  "scale_ckpt": "..."
}
```

### 6.2 EnergyNet

编辑 `scripts/train_energy.sh` 的 `--data_path` / `--log_dir`，或直接用 `train_energy_tray_0810.sh`：

```bash
bash scripts/train_energy_tray_0810.sh
```

作用：在 ScoreNet 多候选上按能量排序，缓解对称/遮挡带来的多峰分布。

### 6.3 ScaleNet（可选）

仅当需要网络估尺寸时：

```bash
bash scripts/train_scale_tray_0810.sh
# 或 scripts/train_scale.sh + --pretrained_score_model_path ...
```

料盘型号固定时，更推荐在推理侧写死 `size_3d`（米），跳过本步。

## 7. 验收指标（不要用错量）

过拟合验收**不要**盯圆盘自转角。建议：

| 指标 | 说明 |
|------|------|
| 盘心 `xyz` 误差（mm） | 主指标；抓取/插取是否对准槽位 |
| 盘面法向 / 倾角误差（°） | 盘是否「站正」 |
| 相邻实例串扰率 | 密排时 mask+姿态是否张冠李戴 |
| 可视化 | RGB 坐标轴 + 3D 框是否贴上沿弧，而非飘到邻盘 |

可用 UI「SAM3 + GenPose2」或 `learning/推理过程详解.md` 中的离线四件套做对比；抓取展示字段见页签中的 `xyzrxryrz`（mm/°）与 `grasp_pose.json`。

## 8. 推理侧配合建议

1. **mask**：宁可略紧贴可见上沿，也不要粘上下游邻盘。
2. **Depth→RGB 对齐**：UI 默认自动估计偏移（失败回退手动 dx/dy）；横向偏差会直接毁掉边缘点云。
3. **点数**：边缘点少时，适当保证实例内有效深度点数，避免离群剔除过狠（UI 中 SOR / MAD 可放宽）。
4. **尺寸**：固定料盘 → 写死 `size_3d`；避免错误尺度反噬可视化与下游抓取框。
5. **跟踪（可选）**：料架固定时，可用上一帧姿态作初值（`tracking=True`），减轻单帧多解。

## 9. 常见失败与对策

| 现象 | 可能原因 | 对策 |
|------|----------|------|
| 旋转乱飞、loss 不降 | 监督了不可观测的自转 | 固定自转角 / 改 pose 定义 |
| 平移整体偏一格 | 训练视角/标定与线上不一致 | 统一相机与高度；查 Depth→RGB |
| 邻盘坐标轴交叉 | mask 粘连 | 先改分割与提示词，再谈姿态 |
| 框尺寸离谱 | ScaleNet 在残缺点云上不稳 | 写死尺寸，停用 ScaleNet |
| 通用权重微调无效 | 分布差太大 | 从零训 + 边缘专用增强 |
